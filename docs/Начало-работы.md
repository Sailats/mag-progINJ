# 🚀 Начало работы

[← На главную](../README.md) · [Окружение разработки →](Окружение-разработки.md)

## 1. Познакомьтесь с проектом

Прочитайте [README](../README.md), затем изучите [окружение разработки](Окружение-разработки.md) и [структуру проекта](architecture.md).

На текущем этапе практические работы посвящены организации репозитория и документации. Для просмотра материалов достаточно браузера.

## 2. Выберите способ работы

### Через браузер

1. Откройте [репозиторий mag-progINJ](https://github.com/Sailats/mag-progINJ).
2. Выберите нужный Markdown-файл.
3. Для внесения изменений войдите в GitHub и откройте редактор файла.
4. Измените текст и проверьте результат в предварительном просмотре.
5. Сохраните изменения с понятным сообщением коммита.

Для прямого сохранения изменений в репозиторий нужны права на запись. Предложения от других пользователей можно передавать через fork и pull request.

### Локально

Установите инструменты, перечисленные в разделе [окружения разработки](Окружение-разработки.md#локальная-работа), затем выполните:

```bash
git clone https://github.com/Sailats/mag-progINJ.git
cd mag-progINJ
```

Откройте каталог проекта в текстовом редакторе и выберите `README.md` или документ из `docs/`.

## 3. Внесите и сохраните изменение

Перед началом следующего сеанса работы обновите чистую локальную копию:

```bash
git pull --ff-only
```

После редактирования файла проверьте изменения:

```bash
git status
git diff
```

Пример сохранения изменения главной страницы при работе в ветке `main`:

```bash
git add README.md
git commit -m "docs: уточнить описание проекта"
git push origin main
```

Если изменён другой документ, укажите его путь в команде `git add`. Для отправки изменений GitHub должен быть настроен на работу с вашей учётной записью, имеющей права на запись в этот репозиторий.

## 4. Посмотрите историю изменений

Откройте [историю коммитов](https://github.com/Sailats/mag-progINJ/commits/main/) и выберите нужный коммит, чтобы увидеть изменённые файлы и сравнение строк.

Локально последние изменения можно просмотреть командами:

```bash
git log --oneline -5
git show HEAD
```

## 5. Проверьте результат

- Заголовки и списки отображаются корректно.
- Таблицы читаются в предварительном просмотре.
- Ссылки ведут к нужным файлам и разделам.
- Названия инструментов и команд оформлены единообразно.
- Сообщение коммита объясняет суть изменения.
