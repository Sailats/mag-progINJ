## Работа через браузер

| Инструмент | Назначение |
| --- | --- |
| Браузер с доступом к интернету | Просмотр файлов и редактирование документации на GitHub |
| Учётная запись GitHub | Сохранение изменений, работа с задачами и обсуждениями |
| Markdown | Оформление заголовков, списков, таблиц, ссылок и блоков кода |

Просмотр публичного репозитория доступен без входа. Для прямого изменения файлов необходимы права на запись в репозиторий.

### Права участников

| Участник | Возможности |
| --- | --- |
| Читатель публичного репозитория | Просматривать и скачивать документацию, изучать историю коммитов |
| Приглашённый коллега после принятия приглашения | Вносить изменения с предоставленными правами `Write` |
| Владелец репозитория | Управлять настройками и доступом участников |

Приглашение становится действующим доступом после его принятия. Владелец проверяет участников и ожидающие приглашения в **Settings → Collaborators** репозитория.

## Локальная работа

| Инструмент | Назначение |
| --- | --- |
| Windows, Linux или macOS | Операционная система рабочего компьютера |
| Git | Получение репозитория, создание коммитов и синхронизация с GitHub |
| Текстовый редактор | Редактирование Markdown-файлов; например, Visual Studio Code |

Для текущего этапа основными инструментами являются GitHub и Markdown. Язык программирования и зависимости приложения будут добавлены после определения его требований.

### Проверка Git

Откройте терминал и выполните:

```bash
git --version
```

Команда должна вывести установленную версию Git. Если команда не найдена, установите Git и повторно откройте терминал.

### Автор коммитов

Проверьте настройки имени и почты:

```bash
git config user.name
git config user.email
```

Если значения отсутствуют или их нужно изменить только для этого проекта, выполните команды из каталога репозитория, заменив значения в угловых скобках своими данными:

```bash
git config user.name "<Ваше имя>"
git config user.email "<Ваш адрес электронной почты>"
```

При необходимости можно использовать адрес `noreply`, указанный в настройках электронной почты вашей учётной записи GitHub. Имя и почта автора коммитов задают подпись изменений; вход в GitHub для отправки коммитов настраивается отдельно.

### Проверка подключения к GitHub

Из каталога локальной копии проекта выполните:

```bash
git remote -v
git ls-remote origin HEAD
```

В списке адресов `origin` должен вести к `Sailats/mag-progINJ`. Вторая команда обращается к удалённому репозиторию и выводит идентификатор его текущего коммита. Успешное выполнение подтверждает доступ к чтению; отправка изменений дополнительно требует авторизации с правами на запись.

Чтобы посмотреть историю изменения этой страницы, используйте:

```bash
git log --oneline -- docs/Окружение-разработки.md
```

На GitHub ту же историю можно открыть на странице файла через **History**. Выберите коммит с уточнением прав доступа и подключения к GitHub, чтобы сравнить первоначальную и обновлённую версии документа.

## Проверка готовности среды

- [ ] Репозиторий открывается в браузере.
- [ ] Markdown-файлы доступны для просмотра.
- [ ] Для редактирования настроен доступ к репозиторию.
- [ ] При локальной работе команда `git --version` выполняется успешно.
- [ ] В редакторе можно открыть и сохранить файл в кодировке UTF-8.
- [ ] Для локальных коммитов настроены имя и почта автора.
- [ ] `origin` указывает на нужный репозиторий, а `git ls-remote origin HEAD` выполняется успешно.
